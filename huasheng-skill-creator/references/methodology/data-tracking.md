# 发布后数据追踪方法论（生成器内核）

这是生成 `references/skill-template/data-tracking.md.tmpl` 与配套脚本时的"抄数据来源"，与 cover-design.md / script-writing.md 等并列。它讲的是**跨平台、账号无关**的发布后数据追踪逻辑；产物填空时把它落成产物自己的 `references/data-tracking.md`，并按覆盖平台选择性复制脚本。

## 为什么发布后数据要单列一环

创作流程（选题→文稿→标题→封面→审查→分镜）产出的是"发出去之前"的东西；发布后数据追踪管的是"发出去之后到底怎么样"。这一环是"记录作品 → 追踪数据 → 复盘 → 反哺创作"闭环的后半段——没有它，创作永远是开环的，好坏全凭感觉。它可单独触发，和创作流程是两件事。

## 账号级 vs 稿件级（两个维度别混）

- **账号级**：整个号的大盘——粉丝累计/新增、播放大盘、逐日趋势、流量来源占比。触发语是"更新账号数据""更新B站账号数据"等，走各平台 `*_account.py`（视频号例外，见下），落 `账号数据/<平台>.md`。
- **稿件级**：单支视频的表现——播放/完播/互动/涨粉/逐小时趋势/进度流失/流量来源。触发语是给一条后台数据页链接或"更新某支视频数据"，走 `*_metrics.py`，落该视频 `数据/<平台>_数据.md`。

**混淆是最常见的错**：用户说"更新数据"没指范围/平台时，先确认，别把账号级当稿件级猛跑，也别默认全量。

## 四平台的技术分野（决定脚本怎么写）

| 平台 | 鉴权方式 | 抓取手段 | 关键特点 |
|---|---|---|---|
| 抖音 | 会话 cookie + 签名接口 | Playwright 截接口 JSON | 稿件级字段最全（进度分析/流量来源/高赞评论） |
| 小红书 | `x-s`/`x-t` 签名接口 | Playwright 截 `response` | 账号昵称从 API 动态取，不硬编码账号名 |
| B站 | 普通 cookie 鉴权、无签名 | 纯 requests | 唯一不需要浏览器的平台；观众画像仅账号级 |
| 视频号 | 登录态签名、双域 cookie | Playwright 截 `response` | `post/post_list` 一次返回全部视频，账号级抓一次即含全部稿件级 |

**cookie 机制统一**：各平台会话 cookie 存在技能根目录的独立文件（`.douyin_cookie` 等，gitignore），过期时让用户从浏览器复制 `document.cookie` 覆盖即可，脚本不改。cookie 是登录态凭据，绝不入库、绝不回显内容。

## 落盘契约（与 workspace-guide 一致，是账号无关设计的关键）

- 稿件级：该视频文件夹 `数据/<平台>_数据.md`，原始 JSON 归档 `数据/数据_raw/`。
- 账号级：`账号数据/<平台>.md`（B站也统一为 `账号数据/B站.md`，不要用别的变体），原始 JSON 归档 `账号数据/raw/`。
- 脚本用 `scripts/_paths.py` 把 workspace 定位为**产物自身** `<技能根>/workspace`——自包含，不跨 skill、不依赖环境变量。这是把 danchaofan-data-tracker 那套"跨 skill 定位创作 skill 的 workspace"简化掉的核心决策：产物装上就能独立运作。

## 发布后回填后台链接（数据追踪的入口）

视频发到某平台后，第一件事是把创作者后台的稿件数据页链接回填进该视频 `视频基础信息.md` 的 `创作后台链接（各平台）` 块对应平台行。之后跑「更新数据」时脚本直接从这里读 `--url`，不用再找用户要。链接形态：抖音 work-detail 含 item_id、小红书 note-detail 含 noteId、B站 upload-manager 含 BV 号。

## 复盘归因框架

复盘不是把数字抄一遍，是追问"为什么"：为什么这条比那条流量高、为什么播放高却吸粉差、为什么被限流。写法——先摆现象（带数字）→ 逐条归因（区分事实与推测，散户/用户自贴的数字口径乱别照单全收）→ 结论 → 可执行的迭代动作。报告落 `workspace/reports/YYYY-MM-DD_<主题>.md`，稳定规律回写进创作侧，驱动下一轮选题/文稿/封面迭代。

## 账号无关化：移植时的三处去账号化

脚本本质是"平台级"（只依赖平台 cookie，对任何账号通用），真正硬编码账号的只有报告标题串。移植 danchaofan-data-tracker 脚本进产物时：
1. 报告标题去品牌 → 中性 `# 账号数据（<平台>）`（小红书本就从 API 动态取名，保留）。
2. B站账号文件名统一为 `账号数据/B站.md`。
3. `_paths.py` 重写为自包含（删掉跨 skill 环境变量与 fallback）。

因此脚本按"近乎逐字复制 + 去账号化"处理，**不做成 `.tmpl`**——保持生成器"脚本无条件复制、只有 .tmpl 填空"的约定。
